The ESP-IDF link configuration's --Map=.../libespidf.map occurs after the
user-supplied map argument, so it is the final map file. It contains both
Rust/Rune objects (for example librune-*.rlib) and the final application link
inputs; it is therefore the map used for this measurement.

Relevant initial isolation failure, retained verbatim as an excerpt:
Missing esp-mqtt submodule. Please run 'git submodule update --init --recursive'

Cause: when only CARGO_TARGET_DIR was overridden, embuild inferred
target/rune-footprint-poc as its workspace and created an incomplete ESP-IDF
provisioning tree there. The corrected commands above pin CARGO_WORKSPACE_DIR
to the real repository root; no ESP-IDF checkout was altered manually.
