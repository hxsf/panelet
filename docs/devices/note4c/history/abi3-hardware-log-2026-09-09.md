## 实机观测

### 刷新期间三键

临时输入组件将三键 click/long_press 绑定到同一 handler，以 State 计数并主动 flush；持续产生全刷。用户按约定依次操作 BOOT、上、下短按，再操作对应长按，最后反馈“已完成”。

| 顺序 | 事件 | 采样 held_ms | 位于物理全刷阶段 |
|---|---|---:|---|
| 1 | BOOT click | 180 | 是 |
| 2 | 上键 click | 180 | 是 |
| 3 | 下键 click | 140 | 是 |
| 4 | BOOT long_press | 1020 | 是 |
| 5 | 上键 long_press | 1020 | 是 |
| 6 | 下键 long_press | 1020 | 是 |

六项均在 `pon_drf_refresh` 起止时间内采集，按序派发，State 计数由 8 增至 14，长按释放没有额外 click。采样统计 captured=17（含基线和正式提示前操作）、overflow=0、pending=0。独立采样线程栈 4096 B，本段最低余量 2780 B。此结果证明所测输入速率下全刷没有阻塞三键采集，不代表任意速率零丢失。

实机使用专门的六绑定测试组件以明确关联事件和刷新时间；Counter 的多绑定与状态行为由主机实际执行覆盖，没有另外让用户对 Counter 重复整组六键实验。

### 显示与生命周期

- 临时组件接受 flush 后主动触发脚本错误：脚本 job 为 failed，已接受画面仍到达 presented；随后 `screen.retry` 对相同像素报告 unchanged。
- 显式进入/退出诊断模式通过。退出后旧队列中的诊断显示命令被拒绝为 `stale diagnostic or display command`，未覆盖恢复后的前台。
- 取消前台并进入诊断模式后执行 USB 串口重启：前台选择仍为空、模式恢复 normal，随后重新激活 TODO。持久化取消与诊断模式不持久化均在最终固件上验证。
- Calendar 0.3.0 与 TODO 0.4.0 在板上编译、运行并完成呈现；Calendar 时钟有效，TODO 保留原本机示例 feed。配置恢复引发新会话后正常执行。
- 最终固件 USB 串口重启后自动恢复 TODO：脚本 `run_finish` 在启动约 40.166 秒出现，提交画面的物理全刷约 40.466 秒开始、64.836 秒结束。管理状态最终为 `presented`、refreshing=false，证明脚本完成与物理显示完成分别报告。
- 输入实验全刷约 19.8 秒；最终启动状态页/前台全刷分别 24,324 / 24,363 ms，断电/深睡清理 167 / 168 ms。均为固件阶段计时，并非示波器测量。
- 最终编译后 worker 栈最低余量 8376 / 65536 B。Rune Context 初始化时内部可用堆 89099→53119 B、PSRAM 可用堆 8346612→7475564 B；脚本结束内部可用堆 86523 B。这些是各时点观测，不是所有负载的内存保证。最终启动日志未发现 watchdog、panic 或栈溢出。

## 迁移结果与限制

新固件首次启动拒绝执行旧 ABI 包，保留其存储；上传同 ID 的新包后恢复配置与前台，没有格式化 assets。最终保留内置组件、Calendar、TODO 三个组件，TODO 前台及原 300 秒间隔恢复，临时输入/错误测试组件已删除。全部三个组件配置与迁移前导出一致；KV/private 保留另外由存储迁移主机测试覆盖。

未人为注入 BUSY 超时、物理屏幕故障或断电清理故障，因此显示硬件失败后的完整设备报告链仍待故障条件验证；相关调度、错误状态及驱动清理路径已有主机覆盖。未测试真实 NAS Basic、第二个真实 AP、真实提醒事项数据或全部长时间运行场景。用户按键确认不等于逐像素/字形视觉验收。历史版本其他测试见 [前一版生命周期记录](lifecycle-hardware-log-2026-09-09.md)，不能自动计入本版通过项。
