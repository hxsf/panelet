# 自动差异窗口刷新实机记录（2026-09-09）

## 设备与版本


NOTE4C Devkit PCB V1.0，USB 连接供电和串口；未测量电压、电流或电池供电贡献。沿用同一板卡已核验原厂备份与恢复条件，另保留上一版应用镜像及配置导出。刷写前重新读取安全状态，核对已保存的完整 Flash 校验和与 ota_0 布局，只通过 `scripts/flash-server.sh` 写入 `0x20000` 应用槽。

固件基于 `52a816854c6045fa8fdabaf57ba71158b675de9d` 的未提交工作树；ELF SHA-256 为 `412f9e338c100f9625386c1e78494e824a2c9cb80f6c679c37b0a0d39e534bb1`。源码差异哈希为 `c8eaa0633f1aae29ef96faa96da858ba76fe2ffb1b34ebe1c3bc05663ddbb5d2`，算法与 [ABI 3 实机记录](abi3-hardware-log-2026-09-09.md) 相同。串口日志、状态迁移快照、临时测试包及回退镜像位于仓库外受控目录。

## 自动测试结果

临时 ABI 3 组件沿用 Canvas 继承语义，分阶段主动提交；没有改动底层显示接口或从测试脚本指定 PTLW 窗口。实际决策均由像素差异产生：

| 目标变化 | 实际方式 | 成功状态 | PON/DRF |
|---|---|---|---:|
| 本代次首次变化：中心黑块 | 全刷 | presented | 正常完成 |
| 中心黑→红 | 局刷，x=160 y=110，80×80 | presented | 24,317 ms |
| 中心红→黄 | 局刷，x=160 y=110，80×80 | presented | 24,335 ms |
| 右下角白→黑小块 | 局刷，x=396 y=296，4×4 | presented | 24,336 ms |
| 整屏改黑 | 全刷 | presented | 正常完成 |
| 再提交相同黑屏 | 不刷新 | unchanged | 无物理刷新 |

**测试预期终态是整屏黑色**：先通过整屏改黑验证大范围变化回退全刷，再重复提交同一黑屏，验证像素去重跳过刷新。黑屏本身不是故障，也不代表局刷把整屏误清空；两次提交的结果分别为 `presented` 和 `unchanged`。

三次局刷均完成关闭窗口、断电/深睡和强制安全清理。主机记录的管理状态与串口窗口及刷新阶段一致；设备提供的管理页 gzip 解压后与本机新版页面逐字节相同。另以 JS 验证 full/partial/unchanged 的刷新方式和区域显示。

本段未见 watchdog、panic 或栈溢出；worker 最低栈余量 8376 / 65536 B，输入任务最低余量 2776 / 4096 B，输入 overflow=0（本段没有安排按键压力测试）。脚本结束时内部可用堆 82103 B；这些只代表本次负载观测。周期第 9 次全刷和故障后回退由主机测试覆盖，本轮未在硬件上注入屏幕故障，也未重复 8 次局刷做寿命实验。

## 操作者目视反馈

用户确认：中心红／黄窗口变化时，窗口外无闪烁或改变；没有看到残影或颜色污染。中心彩色窗口的本次目视验证通过。

右下角 4×4 小块用户没有看见，并提出可能被外壳圆角挡住。此项仅确认驱动执行和状态为成功，**视觉效果未确认**；小尺寸或遮挡只是可能解释，不能据此记目视通过。
